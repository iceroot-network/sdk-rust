The first release. The interfaces below changed shortly before it; code written against earlier development builds needs these changes.

- **`HttpOptions::headers`** (feature `http`): extra headers sent with every request to every relay, for a relay behind a proxy that asks for a token. Their values never appear in the client's `Debug` output, and a header HTTP does not allow is refused without echoing its value.
- **No fee from the node's statistics.** `Draft::build` takes the chain, the request and the online facts; its fee statistics parameter is gone, and so are the `node-statistics` fee source (`FeeSource` is `Floor` or `Explicit`) and the core's `FeeStatistics` and `FeeFigures`. The client's `fee_statistics` call stays, for display. A serialized draft whose fee source names anything other than `floor` reads as `explicit`.
- **No floor without an enabled fee table.** Where the milestone in force has no enabled dynamic fee table, the node's pool applies settings of its own, so there is no floor: `Chain::fee_floor` and `ResolvedFee::floor` are `None`, `Rules::fees.floor_available` is `false`, and `FeeChoice::Minimum` and multipliers fail with `FeeUnavailable`. Such a network needs `FeeChoice::Exact`. A draft never carries a zero fee labelled as the floor.
- **heartwood-core's address.** `heartwood-crypto` is fetched from `ssh://git@github.com/iceroot-network/heartwood-core.git`. A key behind an SSH host alias works through a git URL rewrite in the fetching command's environment; the README shows how.
