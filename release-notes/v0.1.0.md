The 0.1.0 version contains the Rust SDK core, node API client, vote selection library, encrypted keystore, account link CLI, shared bindings, Go WebAssembly exports and Tauri 2 plugin. It is in early development. The API may change before 1.0. Crates are used as git dependencies and are not published to crates.io. This file describes the version prepared for the first release; the release tag has not been created yet.

### Networks and formats

Only the `devnet` profile (network byte 90) is supported today. It uses secp256k1 keys, BIP340 signatures and Base58Check addresses. Transfers, votes, burns, second keys, validator registration and resignation, and message signing are supported. The `devnet-pq` and `id-devnet` profiles are declared with all capabilities disabled. There is no public testnet or mainnet profile.

### Contents

- Recovery phrases, hardened account derivation, addresses and integer amounts. Legacy passphrase import is available on classical devnet profiles.
- Transaction drafts built from chain rules and account facts, offline signing, serialized drafts and explicit fees. A minimum fee requires an enabled dynamic fee table. A deserialized draft's fee is verified as the floor only against the reader's own chain under the documented checks.
- A sans-IO node API client for the Solar-compatible REST API, with typed reads and batched submissions. Optional `http` provides native reqwest transport; optional `serde` provides JSON serialization. Multiple relays are checked against one chain before use, and HTTP redirects are refused.
- Four vote selection modes: Diversity, Reliability, Maximum Rewards and Support Newcomers. Selections are reproducible from the same inputs and carry reasons for review. Checks report changed eligibility without recasting a vote.
- Password-encrypted recovery-phrase entropy using Argon2id and XChaCha20-Poly1305, with desktop, mobile and web presets. The `keystore` feature is enabled by default.
- Checked sign-in messages, version 1 ownership proofs of Solar addresses and version 1 GitHub account links with signed revocations and a no-replay rule. Plain message signing refuses these protected message formats.
- Shared bindings with opaque key handles, WebAssembly exports for the Go SDK, and a Tauri 2 plugin that keeps keys and signing in Rust.

The crypto dependency is fetched from the public Heartwood Core repository over HTTPS without credentials. Format specifications are in `docs/`, and committed vectors check the supported byte formats.
