The first release. The interfaces below changed shortly before it; code written against earlier development builds needs these changes.

- **`HttpOptions::headers`** (feature `http`): extra headers sent with every request to every relay, for a relay behind a proxy that asks for a token. Their values never appear in the `Debug` output of the options or of the client, and a header HTTP does not allow is refused without echoing its value.
- **`HttpClient` follows no redirect** (feature `http`): a relay that answers with one is skipped like a relay that cannot be reached, so a request, its headers and its body never reach a host the relay list does not name. A proxy named by `HTTP_PROXY`, `HTTPS_PROXY` or `ALL_PROXY` in the environment is used, as curl uses it. On Android the client verifies HTTPS against the Mozilla root certificates it is built with (`webpki-root-certs`), since the platform's verifier needs the application's Java environment, which a library cannot set up. There a certificate from a private or user-installed authority is refused, the roots are those of the `webpki-root-certs` version in the application's `Cargo.lock` (a root Mozilla adds or distrusts later arrives only with a rebuild: run `cargo update -p webpki-root-certs` before each release of the application), and no certificate revocation is checked.
- **No fee from the node's statistics.** `Draft::build` takes the chain, the request and the online facts; its fee statistics parameter is gone, and so are the `node-statistics` fee source (`FeeSource` is `Floor` or `Explicit`) and the core's `FeeStatistics` and `FeeFigures`. The client's `fee_statistics` call stays, for display. A serialized draft whose fee source names anything other than `floor` reads as `explicit`.
- **No floor without an enabled fee table.** Where the milestone in force has no enabled dynamic fee table, the node's pool applies settings of its own, so there is no floor: `Chain::fee_floor` and `ResolvedFee::floor` are `None`, `Rules::fees.floor_available` is `false`, and `FeeChoice::Minimum` and multipliers fail with `FeeUnavailable`. Such a network needs `FeeChoice::Exact`. A draft never carries a zero fee labelled as the floor.
- **heartwood-core's address.** `heartwood-crypto` is fetched from `ssh://git@github.com/iceroot-network/heartwood-core.git`. A key behind an SSH host alias works through a git URL rewrite in the fetching command's environment; the README shows how.

It also carries the vote selection library, the keystore and ownership proofs:

- **`iceroot-vote`**, re-exported as `iceroot_sdk::vote`, with `iceroot_sdk::voting` to build a snapshot from the node client's validator list. It selects a vote in four modes (Diversity, Reliability, Maximum Rewards, Support Newcomers), sampled per account and reproducible, and splits and checks votes against the network's rules. Validators a node refuses votes for are left out of a relay snapshot.
- **`iceroot-keystore`**, re-exported as `iceroot_sdk::keystore` behind the default feature `keystore`: a versioned encrypted format for recovery-phrase entropy (Argon2id and XChaCha20-Poly1305, every header byte authenticated), with presets for desktop, mobile and web. Backends that never hold a user's seed can leave it out with `default-features = false`.
- **`iceroot_sdk::ownership`**: build, sign and verify version 1 ownership proofs of Solar addresses, as the legacy signer makes them, for claims.
- **`Mnemonic::entropy()`**, the phrase's entropy, for the keystore.
- **`tauri-plugin-iceroot`**: the SDK as a Tauri 2 plugin, the native implementation of the TypeScript package's interface (`@iceroot-network/sdk/tauri`) for desktop and mobile wallets. Keys and signing stay in Rust behind handles that belong to the webview that opened them, drafts cross as serialized bytes and are read again before signing, node requests go over reqwest to the relays the application's capabilities allow, and the keystore runs natively. It is a workspace of its own (it builds against Tauri and the platform's webview libraries); checked on Linux, built for Android.
- **`HttpClient::exchange`** (feature `http`): sends a request and decodes its answer with the caller's decoder, with the same failover, request budget and backoff as `send`, for a host that keeps its calls in another form.
